# Карта проблем (аудит кода, 2026-06-22)

Глубокий аудит всего `src/` (~57k строк, 309 файлов) + `src-ui/` (68 файлов) шестью параллельными ревьюерами. На момент аудита `npm run lint` и `npm run typecheck` — чисто; всё ниже — логические/runtime/security-проблемы, не ловящиеся компилятором.

Статусы: ✅ исправлено и проверено (361 тест проходит) · ⬜ открыто.

## P0 — Критические

### Порча данных при записи/редактировании XML
- ✅ **BOM/EOL теряются при записи** — `SubsystemXmlService` (updateProperty/updateContentRefs/updateChildSubsystems), `MetadataXmlCreator.addChildElement`, `MetadataXmlRemover` (removeChildElement/removeFromSubsystems) писали `fs.writeFileSync(...,'utf-8')`. Переведено на `writeTextFilePreservingBomAndEol`.
- ✅ **`String.replace` с `$`-раскрытием в значении** — порча свободных текстовых полей (Синоним/Комментарий/текст запроса СКД/тело обработчика). Все динамические замены в `ObjectXmlReader`, `ConfigurationXmlEditor`, `SubsystemXmlService`, `CommandInterfaceService`, `DataCompositionSchemaService`, `form/FormEditService`, `form/FormShared` переведены на function-replacer (`() => value`).
- ✅ **DCS rename-parameter без экранирования** — `DataCompositionSchemaService` вставлял новое имя без `escapeXmlText` → невалидный XML. Исправлено + function-replacer.
- ✅ **Не-nesting-aware `<Properties>`** — `TypedFieldPropertyRules.findPropertiesInner` резал блок на первом `</Properties>` (потеря хвоста при записи). Переведено на `findNestingAwareElementRange`.
- ✅ **Детект типа жёстко по префиксу `v8:`** — `TypedFieldPropertyRules.detectFieldTypeCategories` молча удалял валидные свойства при другом префиксе. Сделан namespace-agnostic regex.

### Краши на штатных операциях
- ✅ **CfeBorrowService.buildInternalInfo** — `GENERATED_TYPES[typeName].length` падал TypeError для `CommonModule`/`Subsystem`/`CommonForm`. Исправлено (`?? []`).
- ✅ **getMetaFolder** (`domain/MetaTypes`) — `META_TYPES[kind].folder` падал на незнакомом типе (ломал `cfe_diff`). Исправлено (`?.`).

### Обход защиты
- ✅ **MCP полностью обходит проверки поддержки/хранилища** (`V8McpServer`) — добавлен guard `assertMetadataEditable`/`assertNodeEditable`, БЛОКИРУЮЩИЙ мутацию (как UI) с понятной ошибкой клиенту. Охвачено 15 мутирующих инструментов над существующими .cf-объектами (set_property/set_properties/set_type, rename_metadata, remove_metadata, remove_form, add_form, edit_subsystem_content, edit_command_interface, edit_role, compile_mxl/skd/form, edit_skd/form, add_help). Создание новых объектов/EPF/ERF/расширений и заимствование намеренно не блокируются.

## P2 — Средние

- ✅ **Процессы/ФС:** `DesignerAgentProcess.stop` — SIGKILL-фолбэк + ожидание exit; `ProcessDesignerAgentTransport` больше не реанимирует disposed-сессию; `DirectorySnapshot.replaceDirectorySnapshot` восстанавливает target при сбое; `HashCache` пишет атомарно (tmp+rename).
- ✅ **Утечки disposable:** `statusBarItem` диспозится; `MetadataTreeProvider` получил `dispose()` и зарегистрирован; universal-панель освобождает `onDidReceiveMessage` и слушает `onDidDispose`.
- ✅ **Парсинг:** ложные ссылки `includes('Kind.Name')` → сопоставление с границами идентификатора; `isRegistered` экранирует имя; формы вставляют в КОРНЕВОЙ `<ChildItems>`/`<Events>` (nesting-aware, не AutoCommandBar); атрибуты читаются и в `'…'` (см. #17).
- ✅ **Vue:** `PropertyTypeControl` watch по подполям + защита фокуса; `<select multiple>` через `:selected`; `:key` по индексу; `url(...)` иконок через `cssIconUrl()` с allowlist схем; `messageBus` валидирует входящее сообщение.
- ⬜ **Секреты в argv** (`onecCommon`, `repositoryCommands` — `/P<pwd>`, `-Pwd`) видны в `ps` → файл параметров `/@`.
- ⬜ **MCP пишет по произвольным абсолютным путям** вне workspace (`V8McpServer` create_epf/erf/configRoot).
- ⬜ **Старт/UI-поток:** `Container.bootstrap` синхронно строит хеш-кэши в activate (отложить нельзя без риска — `reloadEntries` зависит от готовности кэшей; оставлено замечание в коде); полный ребилд DTO дерева на каждый refresh.
