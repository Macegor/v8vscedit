# Конвейер агентной разработки v8vscedit

Опорный документ **оркестратора** (основного чата Claude Code) и всех субагентов. Описывает роли,
порядок, треки и протокол. Определения агентов — в `.claude/agents/*.md`. Обязательный стандарт
качества — [vscode-extension-best-practices.md](./vscode-extension-best-practices.md); контракт
архитектуры — корневой [`CLAUDE.md`](../CLAUDE.md).

## Цель

Управляемый TDD-конвейер вместо «одного чата на всё»: проектирование, написание тестов и реализация
разведены по ролям; ревью и тестирование обязательны на каждой задаче; мелкие задачи не гоняются по
полному треку; документация поддерживается в актуальном состоянии.

## Роли

| Роль | Файл | Модель | Инструменты | Суть |
|---|---|---|---|---|
| **Оркестратор** | основной чат | — | все | Триаж задачи, выбор трека, передача между агентами, синтез результата пользователю |
| **Архитектор** | `.claude/agents/architect.md` | opus | read-only | Изучает ТЗ и код, готовит архитектурный план реализации. Код и тесты не пишет |
| **Автор тестов** | `.claude/agents/test-writer.md` | sonnet | тесты + Bash | Пишет/правит **только тесты текущей задачи**, добивается «красного». Реализацию не трогает |
| **Разработчик** | `.claude/agents/developer.md` | opus | все правки | Реализует по плану до «зелёного», прогоняет **только связанные тесты** |
| **QA / E2E** | `.claude/agents/qa-e2e.md` | sonnet | Bash + правка тестов | После разработчика: **полный** прогон + E2E + покрытие. Отчёт о регрессиях |
| **Ревьюер** | `.claude/agents/reviewer.md` | opus | read-only + Bash | Проверяет соответствие ТЗ, конвенции, SOLID, best-practices, sanity-чеки. Вердикт/возврат |
| **Документатор** | `.claude/agents/documenter.md` | sonnet | доки | В самом конце дополняет `docs/` и инварианты для будущих планов |

## Поток

```
Оркестратор — триаж задачи
   │
   ├── FAST-трек (мелкая, нерисковая):
   │      оркестратор реализует сам
   │        → qa-e2e (полный прогон + покрытие)
   │        → reviewer
   │        → [documenter — если изменился публичный контракт/поведение/архитектура]
   │
   └── FULL-трек (крупная/рисковая):
          architect
            → test-writer (красный)
            → developer (зелёный; только связанные тесты + compile + lint)
            → qa-e2e (полный прогон + E2E + покрытие 100%)
            → reviewer
            → documenter
```

**Инвариант: `reviewer` и `qa-e2e` выполняются ВСЕГДА**, на любом треке. Меняется только объём
предшествующих стадий.

## Триаж: FAST vs FULL

Оркестратор выбирает **FULL-трек**, если задача попадает хотя бы в один пункт:

- правит центральные контракты: `META_TYPES`, `MetaPathResolver`, `PropertySchema`,
  `TypedFieldPropertyRules`, ruleset формата (`infra/xml/format/`);
- добавляет тип метаданных / слот модуля (`ModuleSlot`) / дочерний тег (`ChildTag`) / схему свойств;
- добавляет или меняет MCP-инструмент (`V8McpServer` + `EXTENSION_MCP_TOOLS`) либо канон путей;
- добавляет команду, view/webview-провайдер, декорацию узла, watcher;
- меняет публичный контракт webview ↔ расширение (`src-ui/shared/protocol/`);
- миграции парсинга XML, работа с BOM/EOL, генерация XML;
- затрагивает > 2–3 файлов или пересекает границы слоёв (domain/infra/ui/lsp/cli).

Иначе — **FAST-трек**: локальная правка одного файла, узкий баг-фикс, правка комментария/дока,
переименование внутри модуля. Даже на FAST-треке `reviewer` и `qa-e2e` обязательны.

При сомнении — выбирать FULL-трек: цена лишнего архитектора ниже цены пропущенного риска.

## TDD-петля (FULL-трек)

1. **Архитектор** возвращает план: затрагиваемые слои/файлы по «Инварианту изменений» из `CLAUDE.md`,
   привязка к `META_TYPES`/`MetaPathResolver`, риски, критерии приёмки, перечень необходимых тестов.
2. **Автор тестов** пишет тесты по критериям приёмки на реальных фикстурах (`example/src/cf`,
   `example/src/cfe/EVOLC`) или реальных временных файлах. Прогоняет **только новые/затронутые** тесты
   и убеждается, что они падают **по правильной причине** (красный, не по ошибке компиляции).
3. **Разработчик** реализует по плану минимальным изменением до «зелёного». Меняет не более одного слоя
   за шаг. Прогоняет **только связанные тесты** + `npm run compile` + `npm run lint`. Полный прогон на
   этой стадии не нужен.
4. **QA/E2E** запускает **полный** `npm test` + `npm run coverage` (порог 100% по строкам/веткам/
   функциям/операторам), при необходимости дополняет/чинит E2E (data-driven матрица генерации XML).
   Возвращает отчёт: прошло/упало, покрытие, регрессии.
5. **Ревьюер** проверяет и выносит вердикт (см. ниже).
6. **Документатор** актуализирует документацию.

На FAST-треке шаги 1–2 выполняет оркестратор (реализует сам), далее шаги 4–6 без изменений.

## Протокол возврата (reviewer)

Ревьюер завершает одним из:

- **APPROVE** — соответствует ТЗ, конвенциям, SOLID, best-practices; sanity-чеки и тесты зелёные.
- **RETURN → developer** — дефекты реализации/стиля/SOLID/покрытия. Список конкретных замечаний
  (файл:строка, что не так, чем чревато). Оркестратор возвращает задачу разработчику.
- **RETURN → architect** — расхождение с ТЗ пользователя или архитектурный дефект (утечка знаний из
  `META_TYPES`, нарушение границ слоёв, дублирующий реестр). Оркестратор возвращает на перепроектирование.

После доработки повторяются стадии начиная с точки возврата, затем снова `qa-e2e` и `reviewer`.
Ревьюер проверяет **всегда**, в том числе после мелких правок.

## Обязательства агентов (общие)

Каждый агент перед работой сверяется с:

- корневым `CLAUDE.md` — архитектурные инварианты, запреты, «Инвариант изменений»;
- [vscode-extension-best-practices.md](./vscode-extension-best-practices.md) — обязателен для
  `architect` и `reviewer`;
- профильными `docs/` (`architecture.md`, `metadata-navigator.md`, `mcp-paths.md`,
  `xml-format-rulesets.md`).

Единый источник правды не дублируется в промптах агентов — агенты **ссылаются** на эти документы.

## Границы

- Оркестратор — это основной чат, а не отдельный файл-агент; его поведение задаётся `CLAUDE.md`.
- Субагенты запускаются оркестратором через инструмент Task; они не запускают друг друга напрямую —
  последовательность и передачу результатов контролирует оркестратор.
- Разделение прав инструментов по ролям: `architect`/`reviewer` — read-only (не портят код),
  `test-writer` ограничен тестами, `documenter` — только документация.

## Git-процесс

- Коммиты — на русском, **без упоминаний Claude / `Co-Authored-By`** (см. `CLAUDE.md`).
- **Ветки создаёт только пользователь** — агенты и оркестратор не создают ветки автоматически.
- Перед завершением задачи: `npm run compile` и `npm run lint` — без ошибок и предупреждений;
  `npm test` и `npm run coverage` — зелёные (ответственность `qa-e2e`).
