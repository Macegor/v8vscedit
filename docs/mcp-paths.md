# Канон путей и типов 1С для MCP-инструментов v8vscedit

Документ — единый и обязательный справочник правил именования путей метаданных
и типов 1С, которые принимают и возвращают MCP-инструменты расширения
`v8vscedit`. Целевая аудитория — ИИ-агенты, подключённые к локальному
MCP-серверу расширения, и разработчики этих агентов.

Канон один: только русские формы, без английских алиасов, без legacy-форм
7.7/8.0, с предсказуемой структурой. Любой инструмент, который сейчас принимает
аргумент `path`, ожидает строку строго в этом формате. Любой инструмент,
который возвращает путь к узлу, выдаёт его в том же формате.

Документ соответствует главам 1-2 плана `../MCP_REFACTORING_PLAN.md` и
является обязательным дополнением к разделу «MCP-инструменты модификации
конфигурации» в `../AGENTS.md`.

## 1. Главные правила

### 1.1. Множественное число для корней-коллекций

Корневой сегмент пути для коллекций метаданных — всегда множественное число:
`Справочники`, `Документы`, `РегистрыСведений`, `Перечисления`, `Отчеты`,
`Обработки`, `Роли`. Единственное число (`Справочник.Контрагенты`) — это форма
ссылки в запросах 1С, а не путь метаданных, и MCP такие пути отвергает.

### 1.2. Единственное число для подсистем и псевдо-корней

Подсистемы — единственное число: `Подсистема.Продажи`. Псевдо-корни, у которых
по определению ровно один экземпляр в конфигурации, тоже единственного числа:
`Конфигурация`, `Расширение`.

### 1.3. CamelCase без пробелов

Все сегменты — CamelCase без пробелов, дефисов и подчёркиваний:
`КурсыВалют`, не `курсы валют`, не `КУРСЫ_ВАЛЮТ`. Имена объектов на диске
обычно уже соответствуют этому правилу, потому что 1С EDT не пускает пробелы
в именах метаданных.

### 1.4. Точка — единственный разделитель сегментов

Разделитель сегментов — точка. Точка внутри имени сегмента запрещена:
платформа 1С это правило соблюдает на уровне валидатора имён метаданных,
поэтому резолвер инструментария считает любую точку признаком разделителя.

### 1.5. Реквизиты и табличные части — прямые сегменты

Реквизит и табличная часть присоединяются к корневому объекту напрямую,
без сегмента-роли: `Справочники.Контрагенты.ИНН` (реквизит),
`Справочники.Контрагенты.КонтактныеЛица` (табличная часть). Имена в этих
двух категориях уникальны внутри объекта по правилам платформы — конфликт
разрешения невозможен.

### 1.6. Внутри табличной части сегменты возвращаются

Стоит спуститься на уровень ниже — внутрь табличной части — и сегменты
возвращаются. Колонки идут как реквизиты табличной части:
`Справочники.Контрагенты.ТабличнаяЧасть.КонтактныеЛица.Реквизит.ФИО`.
Это нужно, потому что внутри ТЧ могут быть как реквизиты, так и стандартные
реквизиты с одинаковыми именами.

Тот же контейнерный паттерн — второй прецедент у HTTP-сервисов: `URLTemplate`
(URL-шаблон) — контейнер для `Method` (метод), и путь возвращает сегмент
`Метод` так же, как ТЧ возвращает `Реквизит`:
`HTTPСервисы.X.URLШаблон.T.Метод.M`. В отличие от ТЧ, сам `URLШаблон` —
не прямой сегмент (см. §2.4): `HTTPСервисы.X` не содержит других
одноимённых по возможности коллекций, но URL-шаблон синтаксически
рассматривается как отдельный тип метаданных (`MetaKind`), а не роль внутри
`HTTPService`, поэтому его путь всегда идёт через сегмент `URLШаблон`,
без прямой формы.

### 1.7. Подсистемы — без удвоения сегмента

Иерархия подсистем строится без повтора корневого сегмента:
`Подсистема.Продажи.Розница.Возвраты`, а не
`Подсистема.Продажи.Подсистема.Розница.Подсистема.Возвраты`. Префикс
`Подсистема` присутствует только один раз — в самом начале пути.

### 2.2. Псевдо-корни — один экземпляр

| Путь | Что это |
|---|---|
| `Конфигурация` | Узел корня основной конфигурации, для свойств уровня конфигурации. |
| `Расширение` | Узел корня расширения. |

Псевдо-корни используются как путь для `v8vscedit_configuration_info`,
`v8vscedit_validate_configuration`, `v8vscedit_get_properties`,
`v8vscedit_set_property_by_path` и `parentPath` в `v8vscedit_compile_subsystem`
и `v8vscedit_compile_role`.

### 2.3. Прямые дочерние сегменты — без префикса

| Контекст | Что разрешено напрямую |

| те же | `ТабличнаяЧасть` |
| РегистрСведений, РегистрНакопления, РегистрБухгалтерии, РегистрРасчёта | `Измерение`, `Ресурс`, `Реквизит` |

сообщением, если по случайности пользовательская выгрузка содержит одноимённые
реквизит и табличную часть.

## 3. Канон типов значений 1С

Раздел соответствует главе 2 плана. Реестр типов выдаётся инструментом
`v8vscedit_list_supported_types` (платформенные типы) и
`v8vscedit_list_available_types` (с учётом конфигурации и контекста свойства).
Имена, передаваемые в `v8vscedit_set_type`, — только русские из этого
реестра.

### 3.1. Базовые платформенные типы (новинка: ключевая часть E2)

Базовый реестр платформенных типов теперь живёт в `infra/xml/PlatformTypeRegistry.ts`
и читает данные из `domain/CanonicalNames.ts`. Это ключевая новинка
рефакторинга MCP — раньше эти типы были захардкожены в нескольких местах.
В частности, добавлена поддержка `УникальныйИдентификатор` (XML-токен `v8:UUID`)
как полноценного платформенного типа реквизитов прикладных объектов
и форм.

| Канон (рус) | XML | Контекст |
|---|---|---|
| Строка | String | оба |
| Число | Number | оба |
| Булево | Boolean | оба |
| Дата | Date | оба |
| ДатаВремя | DateTime | оба |
| ХранилищеЗначения | ValueStorage | оба |
| УникальныйИдентификатор | UUID | оба |
| ДвоичныеДанные | BinaryData | оба |
| Картинка | Picture | оба |
| Тип | Type | реквизит формы |
| ОписаниеТипов | TypeDescription | реквизит формы |
| СписокЗначений | ValueList | только формы |
| ТаблицаЗначений | ValueTable | только формы |
| ДеревоЗначений | ValueTree | только формы |
| Массив | Array | только формы |
| ФиксированныйМассив | FixedArray | только формы |
| Структура | Structure | только формы |
| ФиксированнаяСтруктура | FixedStructure | только формы |
| ТабличныйДокумент | SpreadsheetDocument | только формы |
| ФорматированнаяСтрока | FormattedString | только формы |

Контекст:
- «оба» — допустим как тип реквизита прикладного объекта и как тип реквизита формы.
- «только формы» — нельзя как тип реквизита метаданных, только в форме.

### 3.2. Производные ссылочные типы — генерируются по конфигурации

Производные типы генерируются по фактическому составу выбранной конфигурации.
Чтобы получить их, инструмент должен видеть конфигурацию (передан `configuration`,
либо в workspace единственная конфигурация).

| Корневой тип метаданных | Производные (русский ↔ XML) |
|---|---|
| Справочник | СправочникСсылка ↔ CatalogRef, СправочникОбъект ↔ CatalogObject, СправочникМенеджер ↔ CatalogManager, СправочникВыборка ↔ CatalogSelection, СправочникСписок ↔ CatalogList |
| Документ | ДокументСсылка ↔ DocumentRef, ДокументОбъект ↔ DocumentObject, ДокументМенеджер ↔ DocumentManager, ДокументВыборка ↔ DocumentSelection, ДокументСписок ↔ DocumentList |
| Перечисление | ПеречислениеСсылка ↔ EnumRef, ПеречислениеМенеджер ↔ EnumManager, ПеречислениеСписок ↔ EnumList |

## 4. Запреты — что MCP отвергает

MCP-инструменты принимают только канон. Любая попытка передать одну из форм
ниже завершается ошибкой резолвера с сообщением «используй канон».

### 4.1. Английские формы

- `Catalog.X`, `Catalogs.X` — английские имена корней не принимаются ни в одном
  числе. Используй `Справочники.X`.
- `Document.X`, `Documents.X` — то же. Используй `Документы.X`.
- `InformationRegister.X`, `InformationRegisters.X` — используй `РегистрыСведений.X`.
- Внутренние сегменты тоже только русские: `Form.Y` → `Форма.Y`,
  `Command.Z` → `Команда.Z`, `Template.X` → `Макет.X`, `ObjectModule` → `МодульОбъекта`.

### 4.2. Единственное число для коллекций

- `Справочник.Контрагенты` — это форма запроса 1С, а не путь метаданных.
  В MCP — только `Справочники.Контрагенты`.
- `Документ.РасходТовара` → `Документы.РасходТовара`.
- `РегистрСведений.КурсыВалют` → `РегистрыСведений.КурсыВалют`.

Исключение — те самые корни, у которых единственное число каноническое:
`Подсистема`, `Конфигурация`, `Расширение`.

### 4.3. Грязные сегменты

- `Справочники.X.Реквизиты.Y` — лишний сегмент-роль `Реквизиты` (мн.ч.).
  Реквизит присоединяется прямо: `Справочники.X.Y`.
- `Справочники.X.ТабличныеЧасти.T` — лишний сегмент `ТабличныеЧасти` (мн.ч.).
  Используй прямую форму: `Справочники.X.T`.
- `Справочники.X.Формы.Y` — мн.ч. вместо канонического `Форма` (ед.ч.).
  Используй `Справочники.X.Форма.Y`.
- `Справочники.X.Команды.Z` → `Справочники.X.Команда.Z`.

Соответствующие сегментированные роли пишутся в единственном числе: `Форма`,
`Команда`, `Макет`, `СтандартныйРеквизит`, `Реквизит` (только внутри ТЧ),
`РеквизитАдресации`, `ПризнакУчета`, `ПризнакУчетаСубконто`, `Перерасчет`.

### 4.4. Удвоение префикса у подсистем

- `Подсистема.А.Подсистема.Б.Подсистема.В` — повтор сегмента `Подсистема`
  для каждого уровня иерархии. Канон — единичный префикс:
  `Подсистема.А.Б.В`.

### 4.5. Точка внутри имени

Имя объекта 1С не содержит точку — это запрещено платформой. MCP-резолвер
любую точку трактует как разделитель сегментов. Это уберегает агентов от
двусмысленных путей, которые пришлось бы парсить «как платформа».

## 5. Как использовать с MCP-инструментами

### 5.1. Общий аргумент `path`

После рефакторинга E5 у всех инструментов, работающих с одним узлом, аргумент
называется одинаково: `path`. Никаких `objectPath`, `formPath`, `templatePath`,
`rightsPath`, `subsystemPath`, `ciPath` и `modulePath` больше нет. Если
инструмент работает с несколькими путями сразу (`v8vscedit_validate_metadata`),
он принимает массив через `paths`.

Парные инструменты, создающие новый объект внутри родителя
(`v8vscedit_compile_subsystem`, `v8vscedit_compile_role`,
`v8vscedit_add_form`), принимают `parentPath` — канонический путь
родителя (`Конфигурация`, `Расширение`, `Подсистема.X.Y` или корневой
объект).

### 5.2. `v8vscedit_tree` для обзора

Перед любой массовой работой с конфигурацией удобно один раз получить плоский
список канонических путей через `v8vscedit_tree`:

```json
{
  "configuration": "cf",
  "scope": "objects",
  "depth": "objects",
  "include": ["Справочники", "Документы"],
  "limit": 5000
}
```

`tree` возвращает плоский массив строк, без свойств — за свойствами идти
прицельно через `metadata_info`. Это снимает необходимость в пагинации `list`
на больших конфигурациях.

Допустимые значения:
- `scope`: `all` | `objects` | `common` | `subsystems`.
- `depth`: `roots` (только корни), `objects` (корни + объекты), `children`
  (корни + объекты + дочерние элементы первого уровня).

### 5.3. `v8vscedit_resolve_path` для отладки

Если непонятно, как выглядит канон для конкретного объекта в работе агента, —
передай сомнительный вход в `v8vscedit_resolve_path` и посмотри `canonical`.
Инструмент нормализует путь и проверяет существование узла:

```json
{ "path": "Справочники.Контрагенты", "configuration": "cf" }
```

Результат:

```json
{
  "canonical": "Справочники.Контрагенты",
  "exists": true,
  "nodeKind": "Catalog",
  "xmlPath": "…/Catalogs/Контрагенты.xml"
}
```

Если узла нет — `exists: false` без ошибки. Если форма не канон — ошибка с
подсказкой канона.

### 5.4. `v8vscedit_list_supported_types` для выбора типа

Полезен перед `v8vscedit_set_type`, особенно когда конфигурация большая и
агент не знает, какие справочники там есть.

```json
{ "context": "metadataAttribute", "configuration": "cf" }
```

Возвращает группы примитивов и ссылочных типов, отфильтрованные по контексту.
Базовая группа выдаётся даже без `configuration`; ссылочные группы появляются
только при выбранной конфигурации.

### 6.2. Tools добавления дочерних элементов

Каждый инструмент принимает `path` (канонический путь объекта-владельца),
`name` (имя нового элемента) и опциональный `configuration`. Резолвер
проверяет, что тип владельца совместим с типом дочернего элемента: например,
`v8vscedit_add_dimension` потребует регистр, а не справочник.

| Инструмент | Что добавляет | Куда |
|---|---|---|
| `v8vscedit_add_attribute` | Реквизит | Справочник, Документ, ПВХ, ПВР, ПС, БП, Задача, Отчёт, Обработка, ПланОбмена, регистры, общий реквизит. |
| `v8vscedit_add_addressing_attribute` | Реквизит адресации | Только Задача. |
| `v8vscedit_add_tabular_section` | Табличную часть | Справочник, Документ, ПВХ, ПВР, ПС, БП, Задача, Отчёт, Обработка, ПланОбмена. |
| `v8vscedit_add_command` | Команду | Объекты с командами (справочники, документы, регистры, перечисления, журналы документов). |
| `v8vscedit_add_template` | Макет | Объекты с макетами (`templateType` — тип содержимого). |
| `v8vscedit_add_dimension` | Измерение | Только регистры сведений / накопления / бухгалтерии / расчёта. |
| `v8vscedit_add_resource` | Ресурс | Только регистры. |
| `v8vscedit_add_enum_value` | Значение перечисления | Только Перечисление. |
| `v8vscedit_add_column` | Колонку (реквизит ТЧ) | `path` указывает на табличную часть (`Справочники.X.КонтактныеЛица`). |
| `v8vscedit_add_url_template` | URL-шаблон | Только HTTPСервис; `path` = `HTTPСервисы.X`. |
| `v8vscedit_add_method` | Метод | `path` указывает на URL-шаблон (`HTTPСервисы.X.URLШаблон.T`) — тот же приём, что у `v8vscedit_add_column` с табличной частью. |

Для добавления формы используется отдельный `v8vscedit_add_form` с
аргументами `parentPath`/`name`/`purpose`/`autoFill` — он создаёт не только
запись в ChildObjects, но и Form.xml, Module.bsl и регистрирует форму
в `DefaultForm`/`DefaultObjectForm` при необходимости.

## 7. Дополнительные замечания

- Если в workspace несколько конфигураций (`cf` + одно или несколько `cfe/*`),
  большинство инструментов требует параметр `configuration`. Сообщение об
  ошибке перечисляет доступные имена.
- Для CFE канон путей тот же — `Справочники.X`, потому что заимствованный
  объект имеет тот же корневой сегмент. Признак «заимствованный» возвращается
  в DTO выдачи (`borrowed: true`).
- Пути в выдаче всегда канонические. Никаких параллельных алиасов в ответе.
- Если в имени объекта по выгрузке оказался пробел (платформа теоретически
  допускает, EDT — обычно нет), резолвер примет такой узел, но в выдаче
  выделит его кавычками: `Справочники."Имя с пробелом"`. Это маркер опасности —
  такой объект лучше переименовать.
- **Отложено (не реализовано):** read-only-инструмент `v8vscedit_list_database_extensions`
  — список расширений, подключённых к базе проекта (тот же источник, что
  QuickPick команды `v8vscedit.connectExtension`), для ИИ-агентов, планирующих
  подключение/выгрузку расширения без ручного опроса пользователя. Переиспользует
  готовую связку `ExtensionCommandRunner.listConnectedDatabaseExtensions` → CLI
  `list-db-extensions` → `infra/environment/ExtensionListParser.ts` (см.
  [architecture.md](./architecture.md#паттерн-чтение-данных-из-базы-через-пакетный-конфигуратор-file-handoff)) —
  бизнес-логику писать заново не нужно, только регистрация tool'а в
  `V8McpServer`/доменном модуле `registration/`.
