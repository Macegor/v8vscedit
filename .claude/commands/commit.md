Подготовь коммит по правилам `CLAUDE.md` (раздел «Git-процесс»). Параметры: $ARGUMENTS

Правила:
1. **Перед коммитом** — `npm run compile` и `npm run lint` должны проходить без ошибок и предупреждений. Если падают — НЕ коммить, верни пользователю ошибки. (Для нерантайм-изменений `.claude/**`/`.gitignore`/`docs` без кода — compile/lint можно пропустить, но явно отметь это.)
2. **Что добавить** — только явно указанные файлы. **Никогда `git add .` и `git add -A`.** Не добавлять `.claude/settings.local.json` (он gitignored/личный).
3. **Сообщение коммита — на русском.** Категорически запрещено упоминать Claude/ИИ в любой форме: никаких `Co-Authored-By: Claude`, `Generated with Claude Code` и подобных подписей.
4. Структура сообщения: первая строка — краткое описание (что сделано), при необходимости пустая строка + детали. Если правки связаны с задачей/фиксом — укажи контекст.
5. **Не пушить.** Коммит создаётся локально; пуш — отдельное действие пользователем.
6. **Не создавать ветки.** Работать в текущей ветке.

`allowed-tools` в заголовке — это пред-одобрение инструментов на один ход, а не ограничение
(ограничивает `disallowed-tools`). Поэтому грант сужен до конкретных git-команд: голое `Bash`
пре-одобрило бы и `git push`, который эта команда запрещает пунктом 5.

Покажи пользователю черновик сообщения коммита и список добавляемых файлов, затем выполни `git commit` (без `--no-verify`, чтобы хуки/git-проверки отработали).
